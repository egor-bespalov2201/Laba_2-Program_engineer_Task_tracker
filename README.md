## Лабораторная работа №2: Планирование и управление проектом

**Тема:** Настройка GitHub Projects как аналога Azure Boards для управления задачами.

**Что сделано:**
- Настроена Kanban-доска с 5 колонками (New → Approved → Committed → Утверждено QA → Done)
- Созданы метки для классификации задач (epic, feature, story, task, bug, area: backend/frontend)
- Настроены спринты (Milestones) с датами
- Реализована иерархия задач: Эпик → Фича → Story → Task
- Настроены swimlanes (дорожки) "Ускоренная" и "Обычная" с WIP-лимитами
- Настроены кастомные поля (PUL Ticket ID)
- Созданы представления (Views): "Все задачи" и "Веб-задачи"
- Настроена аналитика (Insights): Burn up chart и распределение задач по статусам
- Создана Mermaid-диаграмма рабочего процесса

**Ключевые понятия:** Kanban, Scrum, User Story, Definition of Done, WIP-лимит, Burn up chart.

## Лабораторная работа №3: Квартальное планирование и диаграмма Ганта

**Тема:** Планирование на квартал вперёд с учётом взаимодействия нескольких команд.

**Что сделано:**
- Добавлены метки команд: `team: backend`, `team: frontend`, `team: devops`
- Создано 6 спринтов на квартал (Sprint 4-9, декабрь 2026 — февраль 2027)
- Созданы 4 крупные фичи для трёх команд с зависимостями:
  - Backend: Авторизация через OAuth
  - Frontend: Личный кабинет пользователя (зависит от Backend)
  - DevOps: CI/CD пайплайн
  - Совместная: Интеграция с почтовым сервисом
- Добавлены 9 задач для завершения квартала (тестирование, релиз, ретроспектива)
- Построена диаграмма Ганта (Roadmap) с группировкой по спринтам
- Формализованы зависимости между задачами через ссылки (#6, #8)
- Создана страница Wiki "Квартальное планирование" с описанием методологии Scrum of Scrums

**Ключевые понятия:** Квартальное планирование, Program Increment (SAFe), Scrum of Scrums, диаграмма Ганта, кросс-командные зависимости.

## Лабораторная работа №4: CI/CD со self-hosted runner

**Тема:** Настройка непрерывной интеграции с локальной сборочной линией.

**Что сделано:**
- Добавлен исходный код проекта Task Tracker на Python:
  - `task_tracker.py` — ядро системы (классы Task и TaskTracker)
  - `test_task_tracker.py` — 6 модульных тестов
  - `main.py` — точка входа для демо-запуска
- Установлен self-hosted runner на локальный компьютер (Windows, `D:\actions-runner`)
- Создан workflow-файл `.github/workflows/ci.yml` с 4 шагами:
  1. Checkout code — скачивание кода из репозитория
  2. Show Python version — проверка интерпретатора
  3. Run unit tests — запуск всех тестов
  4. Launch project in demo mode — запуск проекта
- Конвейер успешно выполнен локально (все 6 тестов пройдены, проект запущен)

**Ключевые понятия:** CI/CD, self-hosted runner, GitHub Actions, workflow, unit-тесты, автоматизация сборки.
